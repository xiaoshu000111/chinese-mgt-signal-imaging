# 04 不同长度文本怎么处理

一维信号长度 `T` 等于 token 数，而 GAF/MTF/递归图输出是 `T×T`，CNN 又要求固定输入尺寸。你的数据里文本长度差异很大（点评一句到整段故事），因此长度策略是能否训好的关键之一。

## 核心矛盾

- 图像法天然需要**固定 `T`**。
- 但直接截断会丢失长文后半段；直接把所有信号重采样到同一长度又可能抹掉局部抖动。

## 方案：训练期统一补齐，推理期滑窗聚合

### 训练期（统一到固定 T）

设固定长度 `T_target`（推荐 512，可据显存和平均长度调）。对每条信号 `X`：

1. `len(X) > T_target`：**截断**。保留前 `T_target` 个 token（也可留尾部，作为消融选项）。
2. `len(X) < T_target`：**边缘反射补齐**，即用信号末端值镜像延展到 `T_target`，而不是补 0。补 0 会在图像边缘产生一条与真实信号无关的常数纹理，污染 CNN。

```python
def pad_or_truncate(x, T):
    if len(x) >= T:
        return x[:T]
    return np.pad(x, (0, T - len(x)), mode="edge")   # 边缘反射，不引入人为零纹理
```

补齐后长度统一，转图得到统一 `T×T`，batch 内无需 mask。

### 推理期（滑窗 + 聚合）

长文本不该只取前 512 个 token。对 `len(X) > T_target` 的样本：

1. 用**滑窗**切：窗长 `T_target`，步长 `T_target / 2`，得到 K 个重叠窗口。
2. 每个窗口单独转图、单独前向，得到 K 个 logits。
3. **聚合**：`mean(logits)`（简单稳健）或 `max`，默认平均。

这样既保持固定输入尺寸，又不丢长文信息。

## 其他可选策略（作消融/扩展）

| 策略 | 做法 | 优劣 |
|------|------|------|
| 直接截断（前/后 T） | 只取固定长度 | 简单，丢长文信息 |
| 边缘补齐 | 见上 | 简单，短文本图像有重复区 |
| 滑窗 + 平均 | 见上 | 保留长文，重复计算 |
| 等长重采样 | 对信号线性插值到 T | 保留整体形状，但抹掉局部尖峰 |
| 可变长度 + 自适应池化 | 转图后用 GlobalAvgPool 收成定长 | 工程稍复杂，可保留局部细节 |

## 数据层面的建议

1. 先统计 `token 数` 分布（分位数），选定 `T_target` 覆盖大多数样本（如 95% 分位内），避免大面积截断。
2. 单独评估「超长文本」子集上的指标：如果长文检测性能显著下降，说明当前滑窗/截断策略需要调整，这本身可写成消融小节。
3. `model/source` 字段可帮你做「同一 prompt 不同长度」的分组分析（如 gpt4o 生成的长故事 vs 人类短点评），用于答辩时解释长度与来源的混杂。
