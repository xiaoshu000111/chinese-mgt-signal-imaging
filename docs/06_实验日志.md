# 06 实验日志（持续更新）

本文件是唯一的实验事实记录。**规则：**

1. **当天实验当天记；只追加不删除；结论必须挂在数字下面，没有数字的结论写「待验证」。**
2. **所有运行必须经** **`python run.py <命令> --name <实验名> --purpose <目的>`**：原始输出自动落盘到 `logs/YYYYMMDD_HHMMSS_<实验名>.log`，头部含来源（命令行 + git 版本 + 关键配置）与目的。
3. 本文件的每条实验记录必须回填**日志文件路径**——这里记结论和数字，`logs/` 存完整原始输出，两者互相引用。
4. `logs/` 目录只增不删；失败/中断的日志也保留（排查与错误分析的证据）。

每条记录用下面的模板（复制即用）：

```markdown
## YYYY-MM-DD <一句话标题>
- **日志文件**：logs/20260904_143005_baseline_v1.log（原始输出在此）
- **配置**：channel / method / TARGET_LEN / epoch / lr / 显卡 / 显存峰值
- **结果**：acc / f1 / auc（训练集 + 验证集 + 测试集分列；表格优先）
- **现象**：观察到的意外情况（过拟合、某类召回低、loss 尖刺等）
- **结论 / 下一步**：一句可执行的判断
```

## 2026-09-01 管线修复（正式实验前）

跑实验前修掉了两处会污染结论的系统性问题：

1. **fp16 → fp32 后处理**（`src/signals/extract_signals.py`）

   * 问题：rank 通道靠 `probs > p_true` 的逐元素比较，fp16 舍入会让近平局翻转、低概率 exp 下溢为 0，信号不可复现

   * 修复：logits 前向后 `.float()` 再算 5 条通道；`BATCH_SIZE` 16→8（fp32 大张量显存翻倍）
2. **逐样本 min-max → 全数据集分位数缩放**（`src/imaging/to_image.py`、`signal_to_image.py`）

   * 问题：逐样本归一化把「机器 logp 整体偏高」这一核心判别信息洗掉；且与 docs/01 §2 的实现准则不一致

   * 修复：train 上拟 1%/99% 分位数端点存 `data/processed/scaling_{channel}.json`，dev/test 复用；GAF 输出改固定 `(x+1)/2` 映射，不再逐图拉伸

   * 验证：跨样本一致性测试通过（不同动态范围信号中同一数值 → 相同像素）；`tests/test_imaging.py` 全过
3. **注意事项**：换基础模型重提信号时，必须删旧的 `scaling_*.json`（文件名不含模型信息，会被误复用）

## 2026-09-01 本地 git + rsync 服务器同步方案确定

* 决策：**git 只在本地管理**（版本追溯以本地 commit 为准）；云服务器只跑实验，不装 git

* 日常循环：本地改代码 → `./scripts/sync.sh push` → 服务器跑实验 → `./scripts/sync.sh pull` 拉回 logs/experiments → 本地 git commit 存档

* 入库范围：代码/文档/脚本/tests + `logs/`（实验记录）+ `experiments/analysis`、`ablation.csv`（小体积结果）

* 不入库（rsync 同步）：`data/`（原始 90MB + 生成产物）、`experiments/checkpoints/`（权重按需 pull-ckpt）、`scripts/sync.config`（服务器地址，防泄漏）

* 注意：服务器日志头部「代码版本」显示「非 git 仓库」属正常；版本对应关系看 pull 后本地 commit

* 初始提交：`09d9045`（37 个文件，含本轮全部修复与文档）
