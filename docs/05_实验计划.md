# 05 实验计划（按天）

硬件假设：**2×3060 (12GB)**，磁盘 ≥ 200GB（消融用「训完即删」可降到 \~50GB）。
所有实验结果与结论**当天**记入 `docs/06_实验日志.md`，不攒补记。

## 总原则

1. **先跑通，再跑全，最后跑深**：冒烟 → 全量信号 → baseline → 消融 → 分析。
2. **最贵的步骤只做一次**：信号提取（①）落盘缓存后永不重跑；换基础模型才需要重提。
3. **每组实验有明确的决策门**：达不到门就先诊断，不带病推进。
4. **双卡分工**：消融阶段一卡一组任务并行；提取阶段可单卡跑（另一卡空着留给首个 CNN 训练）。
5. **所有运行必须走** **`python run.py <命令>`**：自动落盘日志（见下节），不允许脱离日志裸跑。

## 日志落盘规范（所有实验统一执行）

* 每次运行自动生成 `logs/YYYYMMDD_HHMMSS_<实验名>.log`，文件名即「时间戳 + 实验名」

* 日志**头部自动写入**：开始时间、来源（完整命令行 + git 代码版本 + 关键配置快照）、目的（`--purpose`）

* 每次运行都带 `--name` 和 `--purpose`，写清这段实验「来自哪天哪步、要验证什么」：

```bash
python run.py train --name baseline_v1 \
  --purpose "D4 基线：logp/GASF，验证决策门 AUC>=0.75；观察 train/val gap 判断过拟合"
```

* 不传 `--name` 时默认 `train_<channel>_<method>`，不传 `--purpose` 时用命令的默认目的

* 当天收工把日志路径填入 `docs/06_实验日志.md` 对应条目的「日志文件」字段；`logs/` 只增不删

* 中途 OOM/报错的日志同样保留——失败记录是排查依据，也是答辩时「做过错误分析」的证据

## D2 信号质量自查（不花卡，最关键的一天）

**目标**：确认「人工 vs 机器」在信号层面真的可分——这是整个课题的前提。

用 D1 的 200 条信号缓存（不够可临时提到 2000 条）：

- [ ] 跑自动自查（一条命令出 KS 表 + 曲线图）：

```bash
python run.py ks --name D2_ks --purpose "信号可分性自查：KS 表 + 曲线图，验证决策门 KS>=0.3"
```

- 产出 `experiments/analysis/ks_{split}.csv`（5 通道类间 KS，降序）与 `logp_curves_{split}.png`（人工 vs 机器曲线叠加）
- 判读：人工曲线应有更明显的下探尖峰；KS 表预期 `rank_norm`、`logp` 靠前

**决策门**：至少一条通道 KS ≥ 0.3 且曲线图肉眼可辨差异。
**不过门怎么办**：换 `Qwen2.5-1.5B` 或 `Qwen2.5-0.5B-Instruct` 重提信号（只重跑这 2000 条验证，确认后再全量）。
**记录**：KS 表、曲线图路径、基础模型选型结论。

## D4 Baseline 训练

**目标**：第一个完整指标锚点。

- [ ] `python run.py train --name baseline_v1 --purpose "D4 基线：logp/GASF，验证决策门 AUC>=0.75"`（3060 约 3-5 小时）
- [ ] `python run.py eval --name baseline_v1_eval --purpose "D4 基线在 test_with_label 上的最终指标"` 得 acc / f1 / auc
- [ ] 注意类别 3:1 不平衡：eval 会同时输出 f1（固定阈值 0.5）与 f1_tuned（dev 上调优阈值）——主口径看 f1_tuned；若 f1_tuned 仍明显低于 acc，再考虑 `pos_weight` 重训

**决策门**：test AUC ≥ 0.75。低于 0.70 说明管线或信号有隐藏问题，回 D2 诊断，不带病进消融。
**记录**：完整训练曲线（每 epoch 的 loss/val 指标）、最终指标、过拟合观察（train/val gap）。

## D5-D7 消融（双卡并行主战场）

**目标**：通道 × 方法消融表 = 中期答辩核心贡献。

优先级排序（不是全跑 20 组，按天递进）：

* **D5**：`rank_norm`、`entropy` × GASF（卡0、卡1 各一组）；再加 `logp` × MTF、RP

* **D6**：上一天的胜者通道 × GADF/MTF/RP 补全；开始「训完即删」清理图像

- **D7**：三通道 RGB 融合实验（`logp + rank_norm + entropy` 各一图层）；`python run.py eval ablation` 汇总消融表
  - 注意：RGB 融合当前**没有代码路径**（`stack_rgb` 未接入管线），需先在 to_image/train 增加 3 通道支持；用哪三条通道等 D5/D6 结果出来再定

**操作要点**：

* 每组任务改 `config.py` 的 `ACTIVE_CHANNEL_IDX` / `METHOD` 后，一条龙跑完（实验名统一 `D5_<channel>_<method>` 这类格式，日志可按名检索）

* 双卡：`CUDA_VISIBLE_DEVICES=0/1` 各起一个终端

* 每组训完：把指标和**该组日志路径**抄进 docs/06，删该组图像目录（权重和 manifest 留着）

**决策门**：消融表能回答「哪条通道 × 哪种图最有效」，且最优组合比 baseline 至少持平。
**记录**：每天收工时消融表快照（增量追加，不覆盖）。

## D8 分组分析 + 模型维度

**目标**：解释「为什么」，这是从跑数到结论的一步。

- [ ] 按 `model` 字段分组评测最优模型：gpt4o / glm / qwen 各自的召回率（预期：与基础 LM 同族的 qwen 文本最难检出）
- [ ] 按文本长度分桶评测（短/中/长），验证长度策略是否引入偏差
- [ ] **长度捷径检查**：再做一次「长度匹配子集」评测——两类各取长度中位数 ±10% 的样本重算指标。若与全量指标差距大，说明 CNN 可能学到了「补齐块长度 ≈ 标签」的捷径（边缘补齐的常数区在图像上是成片的常色块，长度信息被直接画进了图里）
- [ ] 混淆矩阵 + 若干可视化（Grad-CAM 看模型在看图像哪块纹理，答辩加分项）

**记录**：分组指标表 + 一段「发现」式结论（如「qwen 生成文本的 logp 曲线与人工最接近」）。

## 风险与应对

| 风险         | 信号             | 应对                                                     |
| ---------- | -------------- | ------------------------------------------------------ |
| OOM（提取）    | 峰值逼近 12GB      | `BATCH_SIZE` 降 4；中断后直接重跑，已完成的样本自动跳过（断点续跑已实现） |
| 信号不可分      | D2 KS 过低       | 换基础模型；换 Instruct 版；加扰动通道                               |
| 磁盘打满       | `df -h` < 20GB | 删已训完的图像目录；消融期用 `TARGET_LEN=256`                        |
| f1/acc 落差大 | D4 观察          | 看 f1_tuned（dev 调优阈值）；仍低再 `pos_weight` 重训 |
| 长度捷径      | D8 长度匹配子集与全量差距大 | 如实呈现分组指标；或用「等长重采样」转图重跑一组对照 |
